# 第六步：问问旦挞用户体验验收

日期：2026-11-02。依据 `plan.md` 中用户确认的“浅蓝校园”设计实施，产品名为“问问旦挞”。本轮完成界面、交互与本机历史持久化，不重新评价第五步真实问答质量。

## 实现范围

- 浅蓝历史侧栏、白色聊天区、灰白输入框与 `#00529B` 强调色；统一页面标题、侧栏品牌与浏览器标题，使用用户提供的旦挞小猫 Logo。桌面侧栏可收起，390px 窄屏使用抽屉。
- 主页面保留对话、输入与历史入口，移除开发进度、服务状态卡片、独立搜索表单、工具日志及累计检索区。无模型配置、样例模式、连接故障和回答限制仍在相关位置说明。
- 输入框随内容适度增高，支持 Enter/Shift+Enter 与输入法组合事件保护。生成时只显示真实忙碌提示，支持停止；最终回答确认保存后整体展示。
- 回答使用安全 Markdown，支持列表、表格与 W/C 引用，不执行原始 HTML、不启用非 HTTP(S) 链接、不自动请求远程图片。引用展开后可定位，收起后恢复引用焦点；复制给出反馈。
- 最近会话排序、新建、切换、重命名、删除与清空。未发送草稿按会话保存在当前页面内；停止/失败保留问题，切换前等待取消完成。重试及断线恢复先读取服务端已提交记录，避免重复回答。
- 树洞登录与清空放入设置，数据源菜单放在输入框底部，偏好随会话保存。首次允许树洞检索会说明片段发送给模型；仅网页模式继续沿用原有证据隔离。
- 本机 SQLite 存储位于 `.private/history/chat.sqlite3`，保存消息、引用、必要模型上下文、标题、时间与数据源偏好。历史目录及文件限制为当前用户可访问，消息与引用同一事务提交；成功保存后才发出 `final`。密码、token 和 `reasoning_content` 不加入历史数据。
- 中断问题先保存为待完成状态，重启后不会把它展示成已完成回答。删除和清空先提交数据库再更新内存；忙碌会话不能直接删改，取消完成后再操作。

浏览器流程：

1. 桌面 1440×960 的空白和已有会话布局；页面命名、开发面板移除、Markdown 表格、引用展开与焦点恢复、复制原文、刷新、重命名、侧栏折叠及删除。
2. 两段会话切换，消息互不串入；未发送草稿与数据源偏好随原会话恢复。
3. 生成过程中确认新建，先停止再切换；返回原会话后保留问题，不伪造助手回答。
4. 390×844 窄屏抽屉、Escape 关闭与焦点返回、中文组合键不误发、Shift+Enter 换行、脚本与危险链接不执行、登录失败后密码清空而草稿保留；390×450 模拟键盘占用时输入框仍可达。
5. 阅读长回答顶部时，新回答实际完成后仍保留阅读位置，并提供“回到最新”。
6. 后端已提交回答但浏览器丢失响应，自动读取并恢复一次回答；再次刷新无重复。
7. 打开仍在后台处理的会话，完成后恢复回答并清除已提交问题，避免遗留草稿被再次发送。
8. 合成发送故障后保留问题，重新检查不丢草稿，可以成功重试。
9. 清空后刷新仍为空；合成登录成功，首次树洞授权与数据源切换可用，浏览器存储没有合成密码或 token。

浏览器脚本 `scripts/demo_ux.py` 固定使用独立的 `.private/verification/stage6/` 目录、合成账号和 HTTPX MockTransport；所有回答及检索片段标明“合成验收”，不代表真实学校政策。测试使用 `8006/5176`，自动关闭其启动的服务。未读取项目 `.env`，未请求真实 DeepSeek、Tavily 或树洞。

## 边界与后续

- 本机单用户、单进程存储；不支持多个 worker/服务实例同时使用同一历史文件，不提供云同步、跨设备历史或跨会话自动记忆。
- 草稿只承诺当前页面内的会话切换；已经发送但中断的问题才会持久化。旧版随进程退出丢失的内存聊天无法恢复。
- 输入法与软键盘检查使用浏览器合成事件和视口高度变化，尚未在真实手机或操作系统输入法中验收。未做 Safari/Firefox 兼容性验收。
- 本轮没有新增真实外部服务质量评测；第五步的语义、上游可用性和真实 token 过期刷新未主动触发等限制继续有效。
- 第七步实验报告、干净环境验收与作业打包仍待实施。启动新版时需重启旧后端；只刷新页面不能升级仍在运行的 Python 进程。
