# Ask Danta · 问问旦挞 1.0.0

## 中文

Ask Danta 是面向复旦大学校园场景的多源检索问答应用，结合公开网页与经授权访问的旦挞茶楼（树洞）资料，为校园办事、课程学习与校园生活问题提供带来源引用的回答。本次以 **1.0.0** 统一发布从项目初建到当前的完整功能，包括浏览器开发模式和跨平台桌面应用。

### 多来源检索与校园调研

- 支持公开网页搜索与正文读取，以及经授权的树洞搜索、帖子上下文读取和按需配图展示。
- 提供“自动选择”“仅网页”“网页 + 树洞”三种数据源模式；仅网页模式隔离先前对话中的树洞证据。
- Agent 按问题需要规划、选择工具、检索和读取上下文，在时间、工具调用次数及树洞分页预算内执行。
- 内置 `ask-danta-research` Skill，指导校园调研、官方规则与个人经验区分、资料时效核对、多来源比较及引用组织。
- 使用 `W`、`C` 来源编号关联网页与校园资料，可展开查看摘要、链接、日期与截断提示；保留来源不可用和信息不足的说明。

### 问答、核对与交互

- 支持多轮追问、Markdown 答案和可展开的来源资料。
- 实时显示检索、读取、答案核对等执行步骤、工具状态及耗时，并支持停止当前请求。
- 提供答案核对与修订；核对阶段采用非思考模式以降低等待时间，主回答与检索决策仍遵守设置中的思考选项。
- 核对阶段遇到输出截断、空回复、格式错误或上游中断时，剩余预算允许则重试一次；核对仍失败时显示具体错误并允许重发。
- 支持问题和回答复制；最新失败回答在原会话中重新发送，不新增侧边栏对话。
- 支持编辑任一历史用户问题，在当前会话中从该位置重新回答，替换该问题及之后的内容；编辑前明确提示替换范围。目前不提供旧消息版本切换。
- 提交问题后立即清空输入框，已发送问题显示在对话区；发送未成功或主动停止时恢复问题。编辑输入框移除深蓝色焦点轮廓，保留浅色圆角容器。
- 修复 DeepSeek 在非思考核对触发补查后恢复思考模式时的 HTTP 400：请求适配器补齐工具调用所需的 `reasoning_content` 字段，不关闭思考或核对，不将内部思考内容写入聊天记录。其他上游请求错误显示 HTTP 状态码，仍不泄露原始错误正文。

### 本地会话、设置与账号

- 使用 SQLite 保存会话、消息、必要引用片段与执行记录，支持会话新建、切换、重命名和删除。
- 在设置页配置模型接口、模型名称、API Key、思考选项、Tavily 网页搜索以及超时和执行预算，无需手工编辑 `.env`。
- 密钥只写不读，界面仅显示是否已配置；设置保存到本机，重启后恢复。
- 支持在界面中登录树洞，或使用项目提供的交互式登录脚本。树洞凭据由本项目独立保存，未登录也可使用仅网页模式。

### Windows、macOS 与 Linux 桌面版

- Electron 安装包包含前端、Python 后端与调研 Skill，使用者无需另装 Python、Node.js 或 uv。
- 应用使用 Danta 猫咪 logo，移除默认 File、Edit 等菜单栏，保留系统窗口控制与常用编辑快捷键。
- 自动启动独立后端，使用随机回环端口与会话凭证；退出应用时停止后端。页面启用隔离与沙箱，不开放 Node.js 权限，外部链接交给系统浏览器。
- 端口握手与健康就绪各允许等待 120 秒，后端正常退出允许等待 60 秒；超时仍执行清理，减少 Windows 进程启动或清理较慢时过早失败的情况。
- 桌面数据保存在系统用户目录，与源码开发目录分开；升级保留既有设置与会话。

### 开发与构建

- 前端采用 React、TypeScript、Vite，后端采用 FastAPI、HTTPX、Pydantic，通过 HTTP 与 SSE 交互。
- 保留 `npm run dev` 和 `python scripts/dev.py` 浏览器开发方式及 Vite 热更新。
- 提供 `npm run desktop:dev`、`npm run desktop:pack`、`npm run desktop:dist` 桌面启动和构建命令；桌面开发命令构建前端后启动，不提供桌面热更新。
- GitHub Actions 在四个原生平台/架构上执行后端测试、前后端构建、独立后端 smoke 检查与安装包打包，并汇总发布产物。
- 自动化回归包含后端测试，以及浏览器、独立后端与 Electron 启动检查。模拟响应与真实服务验证分开记录，不将构建通过视为所有系统上的完整功能验收。

### 首次使用与当前边界

下载对应系统和架构的安装包，启动后在“设置”中配置可用的模型服务；真实网页搜索需配置 Tavily API Key，树洞访问需取得社区要求的授权并登录。默认网页搜索使用明确标记的合成样例，不能作为真实证据，也不替代模型服务。

本项目是独立开发的衍生应用，面向单用户本地使用。会话与凭据保存在本机，但模型调用会将问题、相关上下文和检索资料发送至已配置的模型服务，搜索词会发送至所选搜索服务；它不是离线模型应用。引用和答案核对不保证事实完全正确，正式政策应以官方信息为准。

当前未接入自动更新、多用户账号体系或跨设备同步。安装包未使用开发者证书签名，macOS 使用 ad-hoc 签名，可能出现 SmartScreen 或 Gatekeeper 提示。升级前退出旧版应用；源码开发数据不会自动迁入桌面版。

## English

Ask Danta is a multi-source research and Q&A application for the Fudan University campus community. It combines public web sources with authorized access to Danta campus forum posts to answer questions about campus procedures, courses, and everyday life, with source citations. **1.0.0** brings together the complete feature set developed since the project began, including browser-based development and cross-platform desktop applications.

### Multi-source search and campus research

- Search the public web and read page content; search authorized campus posts, read thread context, and display post images on demand.
- Choose automatic source selection, web-only mode, or web plus campus sources. Web-only mode excludes campus evidence from earlier conversation turns.
- An agent plans when needed, selects tools, searches, and reads context within time, tool-call, and campus-pagination budgets.
- The bundled `ask-danta-research` Skill guides campus research, distinguishes official rules from personal experience, checks recency, compares sources, and organizes citations.
- `W` and `C` source identifiers link answers to web and campus evidence. Expand sources to inspect summaries, links, dates, and truncation notices; unavailable sources and evidence gaps remain explicit.

### Answers, review, and interaction

- Multi-turn follow-up questions, Markdown answers, and expandable source details.
- Live progress for search, reading, and answer review, including tool status and elapsed time, with a stop action for the current request.
- Answer review and revision use non-thinking mode to reduce review latency; the main answer and retrieval decisions continue to follow the configured thinking options.
- Truncated, empty, malformed, or interrupted review responses receive one retry when the remaining budget permits. Persistent review failures produce an actionable error and can be retried by the user.
- Copy questions and answers. Retry the latest incomplete answer within the same conversation without adding a sidebar entry.
- Edit any earlier user question and continue from that point within the current conversation, replacing the selected question and everything after it. The editor explains the replacement scope before submission. Switching between old message versions is not currently supported.
- Clear the composer immediately after submission and display the submitted question in the conversation. Restore the question when sending fails or generation is stopped. The message editor uses a subtle rounded container without a dark-blue focus outline.
- Fix DeepSeek HTTP 400 errors when non-thinking review requests additional tools and the main loop resumes thinking mode: normalize the required `reasoning_content` field on tool-call messages without disabling thinking or review, or saving private reasoning to chat history. Other upstream request errors include the HTTP status while keeping raw error bodies private.

### Local conversations, settings, and accounts

- SQLite persistence for conversations, messages, necessary citation excerpts, and execution records, with create, switch, rename, and delete actions.
- Configure the model endpoint, model name, API key, thinking options, Tavily web search, timeouts, and execution budgets in Settings without editing an `.env` file.
- API keys are write-only through the settings API; the UI shows only whether they are configured. Settings persist locally across restarts.
- Sign in to the campus forum through the UI or the project's interactive login script. Credentials are managed independently by this application; web-only mode remains available without a campus login.

### Desktop applications for Windows, macOS, and Linux

- Electron packages include the frontend, Python backend, and research Skill. End users do not need a separate Python, Node.js, or uv installation.
- Danta cat artwork is used as the application icon. The default File/Edit menu bar is removed, while native window controls and common editing shortcuts are retained.
- Electron starts a private backend on a random loopback port with a per-session access token and stops it when the application exits. Renderers use isolation and sandboxing without Node.js integration; external links open in the system browser.
- Port negotiation and health readiness each allow up to 120 seconds; graceful backend shutdown allows 60 seconds. Timeout cleanup remains in place to avoid indefinite waits while accommodating slower Windows process startup or cleanup.
- Desktop data lives in the operating system's user-data directory, separate from source-development data. Application upgrades preserve existing settings and conversations.

### Development and builds

- React, TypeScript, and Vite frontend; FastAPI, HTTPX, and Pydantic backend; HTTP APIs and SSE progress events.
- Existing browser development remains available through `npm run dev` or `python scripts/dev.py`, with Vite hot reload.
- `npm run desktop:dev`, `npm run desktop:pack`, and `npm run desktop:dist` provide desktop startup, unpacked builds, and installers. Desktop development builds the frontend before launch and does not provide desktop hot reload.
- GitHub Actions runs backend tests, frontend/backend builds, frozen-backend smoke checks, and packaging on four native platform/architecture combinations, then collects the release assets.
- Automated regression coverage includes backend tests, browser regression tests, and frozen-backend/Electron startup checks. Mocked checks and live-service verification are documented separately; successful builds do not constitute comprehensive functional testing on every operating system.

### Getting started and current limitations

Install the package for your operating system and architecture, then configure a working model service in Settings. Real web search requires a Tavily API key; campus access requires the community's authorization and a login. The default web-search provider returns explicitly labeled synthetic examples, which are not real evidence and do not replace a model service.

This is an independently developed derivative application designed for local, single-user use. Conversations and credentials are stored locally, but model requests send questions, relevant context, and retrieved material to the configured model provider, and search queries go to the selected search provider. This is not an offline-model application. Citations and automated review do not guarantee factual accuracy; consult official sources for formal policies.

Automatic updates, multi-user accounts, and cross-device synchronization are not included. Packages are not signed with developer certificates; macOS uses ad-hoc signing, so SmartScreen or Gatekeeper warnings may appear. Exit the previous version before upgrading. Source-development data is not automatically imported into the desktop application.
